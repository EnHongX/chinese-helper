# 设计记录

## 目标

小学生学习助手先做本地网页 MVP，服务对象是小学生和陪学家长。第一阶段已经完成语文学习核心能力；当前阶段把产品升级为多学科学习入口，但仍避免账号、云同步、AI 生成内容和复杂后台。

## 当前设计决策

- 顶部导航保留 `首页`、`语文`、`数学`、`英文`，让学生先按学科进入。
- `语文` 下保留 `汉字`、`字义`、`组词`、`造句`、`记录`、`听写`，不保留歇后语入口。
- 首页只做学生学习入口，不做营销页。
- 数学和英文当前只做最小入口：数学指向口算练习方向，英文指向单词卡方向，不提前实现完整系统。
- 汉字学习采用“一字一页”分页，避免多个大卡片同时挤在页面上。
- 单字卡片内部使用 Tab：`字形拼音`、`字义`、`笔顺`、`组词造句`。
- 田字格固定为主要视觉中心，包含外框、横中线、竖中线和两条对角辅助线。
- 字体优先使用系统楷体/宋体栈，拼音和声调字号加大，声调符号单独放大。
- 配色使用暖色护眼背景、红色主按钮和绿色词语标签，避免强刺激高饱和界面。
- 笔顺和描红使用 HanziWriter，脚本通过 CDN 加载，并在首页用 `preload` 提前请求。
- 朗读使用浏览器 Web Speech API，不引入云端语音服务；没有中文语音时降级为浏览器默认语音。
- 查询历史使用本地 SQLite，只保存功能、原始输入、识别出的汉字和时间。
- 输入框提供清空按钮，重复查询时减少操作成本。

## 数据策略

- `data/seed-characters.json` 保存少量人工精选字，提供更适合小学生的解释、分级造句、量词搭配等内容。
- `chinese-xinhua` 作为兜底数据源，补齐更大范围的汉字、拼音、部首、笔画数、释义和组词。
- 构建脚本把精选字和兜底数据合并进 `data/generated/chars/*.json` 分片。
- 前端只按输入内容懒加载对应分片，不再使用 `window.CHARACTER_DATA` 全局变量。

## 暂不做

- 不做账号系统和云同步。
- 不做 AI 自动生成内容。
- 不做完整数学题库、英语词库和跨学科学习报告。
- 不做错题本、复习计划、练习统计等完整学习闭环。
- 不做桌面打包；当前只保留未来可扩展性。
